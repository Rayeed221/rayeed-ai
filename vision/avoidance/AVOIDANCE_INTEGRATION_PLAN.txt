OVERVIEW
--------
run_dronet_oak.py runs PULP-DroNet v3 on an OAK-D Lite camera. It produces:
  - collision_prob  [0.0 – 1.0]   : likelihood of imminent obstacle
  - steering        [-1.0 – +1.0] : yaw-rate from CNN
  - depth_mm                       : median center depth from stereo
  - horizontal_bias / vertical_bias: left-right and up-down depth asymmetry

MavlinkBridge (inside the script) sends SET_POSITION_TARGET_LOCAL_NED
velocity commands at ~20 Hz when collision is detected.

Currently the script runs standalone. The goal is to embed it as a
background task inside the main DroneAI stack without changing how it works.


KEY ARCHITECTURAL DECISION: TWO INDEPENDENT COMMAND LAYERS
-----------------------------------------------------------

  LAYER 1 — Mission Layer (LLM + Tool Dispatcher)
    goto_position, takeoff, set_mode, etc.
    Rate: on-demand (seconds between commands)
              |
              | position / mode commands
              v
  LAYER 2 — Avoidance Layer (DroNet background loop)
    SET_POSITION_TARGET_LOCAL_NED velocity commands
    Rate: ~20 Hz, autonomous, NO LLM involved
              |
              | velocity override
              v
         MAVLink / Drone

Why this works at the MAVLink level:
  In ArduPilot GUIDED mode, a velocity command overrides the position
  setpoint for that control cycle only. The next position command from
  Layer 1 resumes normal navigation. No conflict — velocity commands
  are ephemeral. The LLM does NOT call avoidance. DroNet steers
  autonomously; the mission layer pauses and resumes automatically.


STEP-BY-STEP IMPLEMENTATION
-----------------------------

STEP 1 — vision/avoidance/dronet_runner.py  [NEW FILE]
  Extract inference + velocity logic from run_dronet_oak.py into a class.

  @dataclass
  class AvoidanceState:
      collision_prob    : float   # 0.0 – 1.0
      steering          : float   # yaw-rate [-1, +1]
      depth_mm          : float   # median center depth
      horizontal_bias   : float   # left/right asymmetry
      vertical_bias     : float   # up/down asymmetry
      timestamp         : float   # time.monotonic()

  class DroNetRunner:
      def __init__(self, mav_connection_string, model_path): ...
      def get_state(self) -> AvoidanceState | None: ...   # thread-safe read
      async def run(self) -> None:                        # 20 Hz loop
          while True:
              state = self._infer()            # OAK-D frame → DroNet
              self._state = state              # publish for observers
              if state.collision_prob >= threshold:
                  self._send_velocity(state)   # direct MAVLink velocity cmd
              await asyncio.sleep(0.05)

  _send_velocity() is extracted directly from MavlinkBridge in
  run_dronet_oak.py — no changes to that logic.

  run_dronet_oak.py stays intact as the standalone CLI entry point.

STEP 4 — safety_policy.py  [EDIT]
  Add set_avoidance_state() setter and check_avoidance() gate.

    def set_avoidance_state(self, state: AvoidanceState | None) -> None:
        self._avoidance_state = state

    def check_avoidance(self, tool: str) -> tuple[bool, str]:
        GATED = {"goto_position", "set_speed"}
        if tool not in GATED or self._avoidance_state is None:
            return True, ""
        age = time.monotonic() - self._avoidance_state.timestamp
        if age > config.AVOIDANCE_STALE_SEC:
            return True, ""     # stale data — don't block
        if self._avoidance_state.collision_prob >= config.AVOIDANCE_COLLISION_THR:
            return False, (
                f"obstacle: prob={self._avoidance_state.collision_prob:.2f} "
                f"depth={self._avoidance_state.depth_mm:.0f}mm — avoidance active"
            )
        return True, ""

  Add check_avoidance() call inside pre_execute_check() after check_speed().

  This prevents the mission layer from sending a conflicting position
  command while DroNet is actively steering around an obstacle.


STEP 5 — planner.py  [EDIT]
  DroNet handles transient obstacles automatically. The planner only
  escalates when avoidance has been running too long (drone is stuck).

  Add between Phase 1 (hard gates) and Phase 2 (oracle):

    if self._is_airborne() and self._avoidance_state:
        prob = self._avoidance_state.collision_prob
        age  = time.monotonic() - self._avoidance_state.timestamp
        if prob >= 0.90 and age < config.AVOIDANCE_STALE_SEC:
            if self._avoidance_active_for() > 10.0:
                # Still blocked after 10s → escalate
                return PlanDecision("REPLAN", "obstacle unresolved after 10s")
            return PlanDecision("WAIT", "avoidance maneuver in progress")

  _avoidance_active_for() tracks how long collision_prob has been above
  threshold continuously (reset when prob drops below threshold).


STEP 6 — tool_dispatcher.py  [EDIT]
  Enrich the vision_obstacle_check response with live DroNet state so
  the LLM has situational awareness without a new tool:

    avoidance = self._safety_policy.get_avoidance_state()
    if avoidance:
        result["dronet"] = {
            "collision_prob" : avoidance.collision_prob,
            "depth_mm"       : avoidance.depth_mm,
            "steering"       : avoidance.steering,
            "active"         : avoidance.collision_prob >= config.AVOIDANCE_COLLISION_THR,
        }

  No new tools are added. The LLM learns about obstacle state through
  the existing vision_obstacle_check tool it already knows.
