Executive summary

A software-defined drone that takes spoken orders and checks them for safety

RayeedAI turns a standard ArduPilot quadcopter into an assistant that operators command in Bangla. An AI layer interprets intent. A deterministic safety core can overrule it. Any payload release always requires a human decision.

Key takeaway

The operational problem

Current drones need a dedicated pilot, while crises need the operator's hands and attention elsewhere

PROBLEM 1

Operator workload

A section commander or fire officer cannot fly a joystick, read a map and run a radio at once. Today's UAS need a separately trained pilot.

PROBLEM 2

Language barrier

Ground-control software is English-first and menu-driven. Front-line users in Bangladesh think and speak in Bangla, especially under stress.

PROBLEM 3

GPS-denied spaces

Jamming, urban canyons, smoke and indoor fires defeat GPS-only autonomy. The drone has to sense and map its surroundings itself.

RESPONSE 1

Natural-language voice command turns intent into validated flight tools.

RESPONSE 2

Bangla-first interface through a real-time speech model with a Bangla system prompt.

RESPONSE 3

Onboard perception: stereo avoidance, visual-inertial odometry and SLAM mapping.

Key takeaway

RayeedAI removes the need for a dedicated pilot and an English-language interface, while a deterministic safety core keeps the final say over every motion command.

    Components · software & AI trade-offs

    Why each software component was chosen, and its limits

    ComponentAdvantagesDisadvantages · mitigation
    Gemini Live (voice LLM)+ Native Bangla speech, real-time, reliable function calling− Cloud dependency, latency, data sovereignty; preview model may change · mitigated by Layer 2 and the local oracle
    Rule-based safety + FSM+ Deterministic, auditable, fully unit-testable− Fixed thresholds need tuning per airframe · all values live in config.py
    Thinking oracle (qwen3 0.6B)+ Offline, 20–400 ms per call, near-deterministic (T = 0.05)− Small model, limited reasoning · advisory only; falls back to rules on failure
    PULP-DroNet v3+ Tiny CNN, ~20 Hz on VPU, proven in nano-drone research− Trained on a different camera and domain; outputs steering only, no map · stereo depth override, SLAM gate
    RTAB-Map VIO + SLAM+ GPS-free 6-DOF pose, loop closure, reusable maps− Drifts on low-texture surfaces; compute-heavy; parameters are locale-sensitive · locked parameter invariants
    YOLOv6n (COCO)+ Fast, on-device, 3D coordinates per detection− Generic 80 classes, no fire or military classes · retraining on mission data required
    MAVLink / pymavlink+ Open standard; velocity overrides layer cleanly in GUIDED mode− Synchronous calls block · wrapped in threads with a 10 s timeout
    Python asyncio core+ Session and background tasks isolated; non-blocking− Single process; a stray blocking call can stall the loop · code review, thread wrapping
    Key takeaway

    The design pairs flexible AI (LLM, CNNs) with deterministic guards (rules, FSM, timeouts). Each AI component has a non-AI fallback, so no single model failure can command an unsafe action.

    Variant A · Defense

    Army configuration: a squad-level aerial asset

    The same flight core with a ruggedized airframe, an EO/IR gimbal and a modular payload bay. The commander directs it like a radio operator.

    ISR & overwatch

    “Hold 80 m above checkpoint 2 and report movement.” Navigate, hover, run detection, and report geo-tagged contacts.

    Perimeter patrol

    Waypoint loops around a forward post, with automatic return-to-launch on low battery or link loss.

    Convoy route scouting

    Flies ahead of a convoy, flags obstructions and likely ambush points, and reports distance and bearing.

    Building & compound recon

    GPS-denied entry using VIO and SLAM; returns a 3D map of rooms and corridors before troops enter.

    Target location & marking

    Locates and geo-marks a point of interest for a human command chain. The drone reports; people decide.

    Mission payload

    Supply drop, marker or smoke, or an approved mission payload, released only through the authorization chain.

    Key takeaway

    Most of the Army value is in seeing and reporting, which the software already supports. The payload capability is an add-on module under strict human authority.

    Variant A · Payload authorization · step through

    The AI assists. Humans decide. Hardware enforces it.

    Design rules

    payload_* tools are critical; the voice LLM has no tool to arm or release; authorization expires after a fixed window.

    Physical safety

    Independent hardware master-arm; automatic safing on FAILSAFE, RTL or link loss; geofenced no-release zones.

    Accountability

    Every request, authorization and actor is logged with a timestamp; video retained for review; aligned with IHL and ROE.

    Meaningful human control: no autonomous engagement mode exists. Release needs two human decisions and a hardware interlock. Integration specifics are [RESTRICTED · handled outside this brief].

    Variant B · Firefighting

    Fire-service configuration: first on scene, from the air

    A heat-tolerant airframe with a thermal camera and an extinguisher payload. Dispatched by voice while crews are still on the way.

    High-rise fire attack

    Flies to the reported floor, finds the hottest window, holds a standoff distance, and delivers extinguisher units through the opening.

    Early knock-down

    Dry-chemical or self-activating extinguisher units on early-stage fires in markets, factories and warehouses.

    Wildfire spotting

    Patrols for hotspots, geo-tags fire fronts, and reports spread direction to incident command.

    Interior scouting

    Maps smoke-filled stairwells and rooms without GPS, and flags people for rescue teams.

    Hazmat & industrial

    Standoff inspection of chemical, gas or electrical fires before crews commit.

    Incident command view

    Live overhead picture with position and telemetry, plus automatic return on low battery.

    Key takeaway

    The fire variant reuses the voice, safety and navigation core. What it adds is thermal targeting and extinguisher delivery to places ladders and hoses cannot reach quickly.

    Variant B · Suppression sortie · step through

    From “fire on the 9th floor” to extinguisher delivered

    Extinguisher payloads

    Self-activating extinguisher balls (~1.3 kg), dry-chemical canister with burst charge, or a tethered hose.

    Heat & smoke safety

    1.5 m SLAM standoff; altitude and speed hard limits; automatic RTL; thermal ceiling gate planned.

    Drop accuracy

    VIO + GNSS position hold; release point corrected for height and drift; thermal re-check after each drop.

    Key takeaway

    A fire sortie is a short chain: detect, approach, aim, confirm, drop, reassess. One operator confirmation releases each extinguisher.
